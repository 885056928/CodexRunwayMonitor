# Monitor Implementation Plan

> Execute inline using executing-plans, with a build/test checkpoint per module.

**Goal:** Deliver a standalone Windows WPF monitor and runnable x64 distribution.
**Architecture:** Core library owns API, disk state, detection and polling. WPF owns UI, notifications and tray. Dependency-free executable tests exercise core with controlled HTTP responses.
**Tech Stack:** .NET 10, WPF, System.Text.Json, HttpClient, NotifyIcon.
**Spec:** ../specs/2026-09-15-monitor-design.md (approved by user).

## Global constraints

- No AI, Codex API or local model proxy dependency.
- Default interval 5 minutes, minimum 3; persisted rolling request quota and server cooldown.
- Null effectiveAt is valid and displayed as unknown; never replace it with announcedAt.
- Save processed IDs before notification; atomic disk writes with backup.
- Chinese UI, local displayed time, UTC persisted time; no production NuGet dependencies.

## Tasks

- [x] API: Models.cs defines ResetEvent and settings; ApiService.cs exposes Task<ResetEvent?> GetLatestAsync(CancellationToken). Tests/Program.cs uses real fixture and injected HttpMessageHandler; assert id, null time, empty data, malformed/missing fields, status errors, timeout and cancellation. First run stubs to observe failure, implement, then `dotnet run --project tests/Monitor.Tests`.
- [x] Persistence/detection: JsonStore<T>.Load/Save plus EventProcessor.ProcessAsync; persist HashSet<string> and high watermark. Assert first-run silence, restart dedupe, older-event suppression, equal-time new ID, repaired timestamps, failed save and corrupted main/backup. Implement and rerun tests.
- [x] Monitor: MonitoringService.StartAsync/PauseAsync/CheckAsync/DisposeAsync, immutable status snapshots, nonblocking gate, cancellation, request ledger/cooldown, safe event dispatch. Tests with blocking handler verify overlap suppression, pause cancellation and failure recovery; test quota by persistent ledger. Build and rerun all tests.
- [x] UI: App handles single instance and lifecycle; MainWindow renders status; SettingsWindow validates and applies settings; NotificationWindow centers on primary screen with DPI; TrayService shares commands and state. Shared App.xaml resources and DESIGN.md own visual choices. Build after each window and verify using WPF smoke harness.
- [x] Delivery: Self-contained win-x64 folder, launch script, README config/API/test instructions. Run release tests, WPF smoke, real API probe, publish and executable start/exit smoke. Record remaining hardware/long-duration checks honestly.
