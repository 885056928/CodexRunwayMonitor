# CodexRunway Monitor 设计草案

状态：用户已确认设计；应用已实现，验证结果见 ../../test-results.md。

## 技术与方案

采用 C# / .NET 10 LTS / WPF。一个独立桌面进程，Core 类库负责请求、事件判定、持久化和调度；WPF 项目负责窗口和系统托盘；测试项目注入假 HttpMessageHandler 和时钟。生产代码优先只依赖框架库，通过 Windows Forms NotifyIcon 提供托盘。

这是推荐方案：核心逻辑可独立测试，同时保持部署简单。所有逻辑塞入窗口代码较短，但不利于取消和重启测试；Windows Service 加独立 UI 增加安装、权限和跨进程通信，不符合本项目轻量需求。

## API 与时间

真实数据见 ../../api-verification.md。严格按 ok/data/meta 和真实字段建模，只处理 reset_completed。id 必须非空。effectiveAt 必须存在但允许显式 null，显示“实际重置时间未知”；announcedAt 单独显示“公告时间”。不以公告时间填补实际时间。无效日期、缺失必要字段和错误响应不更新有效状态。

## 去重和持久化

首次成功获取有效记录只建立基线，默认静默。保存已处理 ID 集合、最后有效记录及已知时间高水位，避免 API 回退为旧记录之后重复提醒。相同 ID 的文字或时间修订可刷新展示，不作为新事件。

未知 ID 且有效时间晚于高水位时视为新事件；明确早于高水位的记录只纳入已见集合。若 actual 时间未知，以已见 ID 判断，不声称能确认其真实时间先后，因此站点补录无时间历史事件可能触发一次提醒。这个限制应在 README 明示。

先原子保存已处理状态，再发 UI 通知。保存失败不通知、不推进内存基线，下轮重试。这个顺序优先保证不重复；若进程恰好在保存后、弹窗前终止，可能漏一次通知，应如实说明，不能声称跨崩溃严格恰好一次。

配置、状态和日志位于 %LOCALAPPDATA%/CodexRunwayMonitor，避免安装目录写权限问题。原子替换并保留备份；配置损坏保留故障文件并回退默认值；状态损坏优先恢复备份，不能恢复则重新静默建立基线并报告。使用单实例互斥防止并行程序重复提醒。

## 调度与网络

默认启动立即检查，然后每 5 分钟异步轮询；单一调度任务和互斥保护防止手动与自动请求重叠。暂停取消本轮请求和后续定时，恢复立即检查；退出等待取消完成再释放资源。

HttpClient 每次请求通过关联 CancellationToken 设置默认 30 秒超时。网络、HTTP、JSON 和存储错误更新状态并写日志，不终止调度。默认不立即重试，留待下一轮，减少共享额度消耗。

检查间隔最小 3 分钟，默认 5 分钟。所有请求包括手动检查共用持久化的滚动额度记录与 429 冷却时间，结合服务端 Retry-After / retryAfter，冷却期间显示可重试时间。其他客户端共享出口造成的 429 仍由服务端响应处理。休眠恢复后检查一次，不补发积压轮次。

## 界面

中文主窗口：监控状态、检查间隔、上次尝试/成功/下次时间、API 状态、最新事件和五个操作按钮。简单浅色布局，明确错误和暂停状态。设置窗口验证输入，保存后更新调度。

提醒用非模态 WPF 置顶窗口，按主屏工作区及 DPI 居中；默认 10 秒自动关闭，0 表示手动关闭，可选系统声音。UI 创建和关闭异常记录日志，不阻塞轮询。通知关闭时新事件仍计为已处理，重新启用不重放历史。

托盘显示状态和时间，提供立即检查、开始、暂停、设置、日志、退出。默认关闭/最小化主窗口隐藏至托盘；关闭此设置后关闭主窗口退出。退出释放图标、窗口、计时器和 HttpClient。开机启动仅在用户开启设置时写 HKCU Run，默认关闭。

## 分阶段验证

1. API Service：真实响应 fixture、null 数据、缺字段、无效 JSON、HTTP 422/429/502/503、超时和取消。
2. 事件逻辑：首次静默、重复、重启恢复、已知旧 ID 回退、时间为空、修订、存储失败和损坏恢复。
3. 调度：无并发、暂停/恢复、手动请求、异常后继续、429 冷却与取消退出。
4. WPF 和托盘：逐模块构建；实际启动和直接 API 检查；弹窗、配置和退出烟雾验证。
5. 发布 Windows x64 自包含程序和中文 README。真实多显示器、系统休眠和长时间稳定性需要区分实际执行与尚未执行的验收，不能用单元测试冒充现场验证。
