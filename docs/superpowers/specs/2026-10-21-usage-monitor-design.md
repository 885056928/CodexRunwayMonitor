# 使用情况统计设计

用户已确认：独立 Windows 管理程序；明确告知、默认开启且允许关闭；先交付本地程序和部署文件，不连接或部署到真实服务器。

## 行为与数据

- 普通客户端启用时约每 60 秒发送随机安装 ID 与版本。服务器从连接读取公网 IP，不信任请求体中的 IP。
- 最后心跳距服务器时间不足 180 秒才算在线；显示在线客户端数和不同 IP 数，不将其称为真实人数。同一公网 IP 可有多个客户端。
- 随机 ID 保存在本机应用数据目录；不收集机器名、用户名、文件、账户或硬件标识。退出或关闭上报立即取消心跳，不影响原有监控及提醒。离线最多经过在线窗口后从统计中消失。
- 服务端状态仅保存在内存，过期数据定期清理，不保留历史 IP、历史使用记录或数据库。服务重启后由后续心跳恢复。
- 普通客户端的 `EnableUsageReporting` 默认 true，主窗口和设置中明确说明内容及关闭方式。部署端点文件 `usage-endpoint.json` 初始为空；未配置地址和接入码时不发送请求。

## 接口约定

- `POST /api/usage/heartbeat`：Bearer 上报接入码，JSON `installationId`（非空 GUID）、`version`（1–64 个 ASCII 字母、数字、点、加、减、下划线）。成功 204。
- `GET /api/usage/clients?page=1&pageSize=50`：独立 Bearer 管理密钥；返回 Core 的 UsageSnapshot，分页上限 100。客户端数组按安装 ID 稳定排序。
- `GET /health`：仅健康状态，不公开统计数据。
- 两种密钥各为 32–128 字符且不同，配置缺失时服务拒绝启动。上报码不等同可信设备认证，统计不用于计费、授权或实名人数判断。
- 请求体上限 4 KiB；限制每个来源 IP 的请求频率，默认每分钟 600，可配置；在线状态容量上限 10000，拒绝过量新增记录。超过限额返回 429，不自动密集重试。
- HTTPS 公网接入。仅允许本机回环 HTTP 用于本地联调。部署时 Kestrel 仅绑定 127.0.0.1:5088，经 Nginx HTTPS 反代；只信任回环代理，Nginx 覆盖来源 IP 请求头。

## 程序结构

- 共享 DTO、端点校验、上报与管理 HTTP 客户端复用 Monitor.Core；上报连接与原 API 的 HttpClient、调度及额度分离。
- 新增 Monitor.UsageServer（ASP.NET Core 10）和 Monitor.UsageAdmin（WPF），不增加 NuGet 包。
- 管理端显示在线数量、IP、版本、安装 ID、最后心跳；连接后每 10 秒刷新当前页，支持分页、手动刷新与断开。管理密钥只保留在内存，界面掩码，断开/退出清空；不放进普通客户端或日志。
- 管理端复用现有 WPF 主题与命令源文件。需要覆盖加载、空结果、错误、断开和键盘操作。

## 验证与交付

真实本机 HTTP 联调、虚拟时钟心跳/过期测试、开关取消、未配置不联网、密钥隔离、伪造 IP、限流、分页和 WPF 窗口检查。提供本地启动帮助、Ubuntu systemd/Nginx 示例与部署说明。公开服务器、域名、证书和真实部署留待服务器准备后处理。
